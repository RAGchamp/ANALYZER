ANNUAL REPORT ANALYZER
Annual Report Analyzer · Foot Notes · Flask + Claude Code

How the Annual Report Foot Note Analyzer Works

A local Flask web app that answers in-depth questions about the notes to the financial statements in an annual report PDF. It does not hand a 508-page PDF to an LLM. It finds the exact note a question needs (e.g. Note 21, PDF pages 405–407) deterministically from the page text and fonts, extracts only that note with its tables intact, and sends that small extract to Claude Code for the analysis. Every question also carries the company's four primary financial statements (Profit and Loss, Balance Sheet, Cash Flow, Changes in Equity), loaded when the report is selected, so Claude can explain how each note affects them. This document walks through how each stage works, the real bugs found while building it, and the fix for each.

1. What the App Does

Code: C:\Daya\RAGchamp\ANN-RPT-ANALYZER\WEB-APP. Start it with python app.py and open http://127.0.0.1:5000. The user goes through six steps:

  1. Select an annual report PDF from ANN-RPT-ANALYZER\Annual-reports\. The app indexes its notes and loads its primary financial statements (consolidated and standalone), rotating any sideways pages first. A View the financial statements link opens them all as tables in a new tab.
  2. Ask a question, e.g. "Analyze the company's Tax related liabilities and comment on it."
  3. Identify the relevant notes. The app uses the consolidated notes by default, unless the question asks for standalone. It then always pauses so the user can confirm or edit the choice.
  4. Extract exactly those notes from the PDF.
  5. Send the question, the note extract and the matching primary statements to Claude Code (claude -p).
  6. Present the analysis, including an Impact on the financial statements section. The user can then ask follow-up questions on the same notes.

The expensive, non-deterministic part (the LLM) only sees a few tens of thousands of characters of exactly the right content: the selected notes plus the four statements they belong to. Everything before it (finding notes, page ranges and tables) is deterministic Python that gives the same answer every run.

2. Architecture

the pipeline
Browser (templates/index.html + static/app.js)
   |

   |                              |- detect_scope()        rule-based: consolidated / standalone / both

   |                              '- keyword_select()      fallback if the call fails
   |
   |  (user confirms / edits the notes in the browser)
   |
   |  POST /api/analyze    --> job: extractor.py           clipped note text + tables as "a | b | c"
   |                                statements.py          + the section's 4 primary statements (cached)
   |                                claude_client.py       Claude call #2: claude -p (stdin, no tools)
   |                                history.py             Prompt-History/  (question, answer, full prompt)
   |                                report_html.py         Analysis-history/<pdf>-<n>-<timestamp>.html

   |
   '  GET  /api/jobs/<id>  <-- the browser polls every 1.5s until done

There are two Claude calls per question. A small, fast one picks the notes (it only sees the list of note titles and sub-headings), and a big one does the analysis (it sees the extracted notes plus the primary statements of the same section). Neither call ever sees the whole PDF.

Reused from basic-chatbot

The Claude interaction reuses the design from C:\Daya\RAGchamp\basic-chatbot\app.py:

  • A fresh, stateless claude -p process for every request, using the local Claude Code login (no API key).
  • --system-prompt to replace Claude Code's default "software engineering assistant" identity. Here it is a financial analyst.
  • The last prompt goes to claude-prompt-input.txt and the last reply to Claude-prompt-output.txt.
  • Every Q&A is numbered in Prompt-History\, carrying on from the highest number already on disk (next_sno() / save_history()).
  • The same error handling: CLI not found, timeout and non-zero exit each become a readable message.

3. Stage 1: The Notes Index (notes_index.py)

What the sample PDF actually looks like
  • No bookmarks. doc.get_toc() returns an empty list, so note locations have to come from the page text.
  • PDF page ≠ printed page. PDF page 405 has 402 printed on it, an offset of 3. The app works in PDF page numbers internally and shows both.
  • A running header on every notes page says which section it belongs to: Notes to Consolidated Financial Statements (PDF pp. 348–503) or Notes to Standalone Financial Statements (PDF pp. 210–327).
  • Note headings share one font: Lato-Black 10pt at the left margin, e.g. 21. INCOME AND DEFERRED TAXES. When a note runs over pages, its heading repeats with (CONTD.).
  • PyMuPDF must be imported as import pymupdf. A conflicting fitz package installed on this machine breaks import fitz.

build_index() reads every page once. pdf_utils.page_rows() merges text spans that share a baseline into visual rows, each with its position, font, size and bold flag. That merge matters because the heading 1. and CORPORATE INFORMATION are separate spans in separate PDF blocks. A row is a note heading when it is:

  1. bold and within 25pt of the page's left margin,
  2. a match for HEADING_RE (number, optional sub-number, optional dot, title),
  3. in the dominant heading font for that section, so bold table labels in other fonts don't qualify,
  4. and in sequence: the note number must be 1–4 more than the previous note. This rejects stray bold numbers.
notes_index.py (excerpt)
HEADING_RE = re.compile(r"^(\d{1,3})(?:\.(\d{1,2}))?\s*\.?\s+(\S.*)$")
CONTD_RE = re.compile(r"\(\s*CONT(?:D|INUED)?\.?\s*\)", re.I)
MAX_NOTE_STEP = 4

Where a note ends: note N ends just before note N+1's heading. If that heading is the first thing on its page, note N ends on the previous page; otherwise it ends mid-page at the heading's y-position. Note 22's heading is at the top of PDF page 408, so Note 21 runs from page 405 to the bottom of page 407:

cache/Bharat-Forge-IR-2026-conv-single-page.notes-index.json (excerpt)
{
  "no": 21,
  "title": "INCOME AND DEFERRED TAXES",
  "start_page": 405, "start_y": 169.0,
  "end_page": 407,   "end_y": null,
  "printed_pages": "402-404",
  "subheadings": ["Statement of profit and loss:", "Profit or loss section",
                  "Reconciliation of tax expenses and the accounting profit ...",
                  "Deferred tax asset (net)", "Deferred tax expense/(income)", "..."]
}

The index is cached as JSON and rebuilt only when the PDF's size or modified time changes. Building it takes about 6 seconds for the 508-page report. While reading every page, it also finds the company name: first from the auditor's report ("To the Members of Bharat Forge Limited"), then from the most-mentioned "… Limited" name, then from the file name. The same pass also looks for the primary financial statements (next section).

Bug: sections started 20 pages too early (PDF p.328 instead of 348)

A page counted as a notes page if the header text appeared anywhere on it. The Independent Auditor's Report (p.328) and the corporate governance pages mention "Notes to Consolidated Financial Statements" in their body text, so they were treated as notes pages.

Fix: the header must be the running-header row at the top of the page

pdf_utils.find_header_row() accepts the match only if it is a row in the top 20% of the page. The ranges then came out exactly right: consolidated 348–503, standalone 210–327.

Bug: notes 3, 5, 9, 11, 14 and 18 were missing

To skip the running header, the body was taken to start below any "for the year ended / as at" row in the top 30% of the page. But table column headers also say As at. On pages where a note began with a table, the "header" cut-off moved down to y≈250 and the note heading at y≈169 was thrown away with it.

Fix: only the sub-line directly under the header counts

The "for the year ended…" row now counts as part of the header only when it sits within 30pt below the section header row. The result was all 59 consolidated notes found, numbered 1 to 59 with no gaps.

Dead ends: headings that don't look like headings
  • 5 INTANGIBLE ASSETS AND GOODWILL has no dot after the number, so the dot in the regex had to be optional.
  • Note 54 never appears as 54., only as sub-headings 54.1 DETAILS OF FUNDS… and 54.2 ….
  • Standalone Note 3's heading is on PDF p.233, a rotated landscape table page. Its text runs vertically, so no horizontal heading row exists.
Fix: sub-numbers and "(CONTD.)" repeats as evidence

A sub-heading N.M whose major number N hasn't been seen yet starts note N. A (CONTD.) repeat of a note that was never seen starting (3. PROPERTY, PLANT AND EQUIPMENT (CONTD.) on p.234) means its real heading was unreadable. The note is then assumed to start at the top of the previous page and marked "inferred_start": true. Final result: 59 consolidated + 56 standalone notes, none missing.

4. Stage 2: Loading the Financial Statements (statements.py)

Why the statements are needed

A note explains a line of a primary statement. Note 21 explains the tax lines of the Profit and Loss, the deferred tax lines of the Balance Sheet, "Income taxes paid" in the Cash Flow Statement, and the tax on OCI items in the Statement of Changes in Equity. To say how a note affects the financial statements, Claude has to see them. So when a report is selected, the app also loads the four primary statements for both the consolidated and the standalone sections, and sends the relevant set with every question.

Finding the statements

While build_index() reads every page, each page that is not a notes page goes to statements.detect_statement_page():

  1. A cheap filter first: the page text must mention "balance sheet", "profit and loss", "changes in equity", "cash flow", "income statement" or "financial position".
  2. The title row is the largest row of at least 14pt in the top 25% of the page. In the sample report the titles are 22pt, e.g. Consolidated Balance Sheet.
  3. The title, with "Consolidated"/"Standalone" and "(Contd.)" removed, must start with one of four statement names. Common alternative names are accepted too: Income Statement, Statement of Cash Flows, Statement of Financial Position, Statement of Changes in Stockholders' Equity.
  4. group_statements() gives each notes section the statement pages that sit in the 15 pages before its first notes page, grouped by type. The section therefore comes from the position of the pages, not from the title's wording (the standalone titles don't say "Standalone").
StatementConsolidated (PDF pages)Standalone (PDF pages)

Balance Sheet341205
Cash Flow Statement346–347208–209
Statement of Changes in Equity344–345, printed sideways207
Problem: the consolidated Statement of Changes in Equity is printed sideways

On PDF pages 344–345 the wide equity table is printed rotated. The page itself is not rotated (page.rotation == 0), but 189 of its 192 text lines run bottom-to-top (line direction (0, -1)). Read as-is, the title isn't a horizontal row at all and the table's rows come out as columns. The first attempt, page.set_rotation(90), did not help: PyMuPDF still reported the text with direction (0, -1).

Fix: draw the page onto a new landscape page, turned 90° clockwise

dominant_direction() finds the most common line direction. If it is sideways, derotated_page() draws the page onto a new, temporary landscape page with the content turned the other way. The text then really is horizontal (189 lines with direction (1, 0)), and the normal title detection and row extraction work unchanged.

statements.py (excerpt)
DERO_ANGLES = {(0, -1): -90, (0, 1): 90, (-1, 0): 180}   # text direction -> turn

def derotated_page(doc, pno, angle):
    src = doc[pno - 1].rect
    temp = pymupdf.open()
    width, height = (src.height, src.width) if angle in (90, -90) else (src.width, src.height)
    page = temp.new_page(width=width, height=height)
    page.show_pdf_page(page.rect, doc, pno - 1, rotate=angle)
    return temp, page

The rotation is stored per page ("rotation": -90), and the extract says so: --- PDF page 344 (printed page 341) (printed sideways; rotated 90° clockwise before extraction) ---. On the rotated page, the running header and page number are now sideways and are dropped. The printed page number is read from the original, upright page instead.

Bug: page 345 wasn't found

After rotation, the (now sideways) running header "Integrated Annual Report" on the odd page landed on the same line as the title, so the title row read Consolidated Statement of Changes in Equity Integrated Annual Report. An exact title match rejected it, and only page 344 was loaded.

Fix: match the statement name at the start of the title row

The title patterns are now matched as a prefix (^(?:statement of changes in … equity)\b). Both pages 344 and 345 are found, and all eight statements (four consolidated, four standalone) load.

Bug: neighbouring numbers merged into one cell

The equity statement has 12 value columns packed tightly, some less than the 12pt COLUMN_GAP apart. So _rows_to_text() produced 127.36 3,230.48 and (327.53) 91,249.54 as single cells, putting the figures in the wrong columns.

Fix: two numbers side by side are always separate columns

In extractor._rows_to_text(), spans are joined only if they are close together and not both numbers (NUMBER_CELL_RE). The rule applies to the notes as well. Real output from the rotated page 344:

- Profit/(Loss) for the year | - | - | - | - | 10,796.61 | - | - | - | - | 10,796.61 | 97.37 | 10,893.98
Balance as at March 31, 2026 | 23,103.22 | 15.50 | 127.36 | 3,230.48 | 68,659.35 | 4,213.27 | (944.15) | (148.19) | (3,414.71) | 94,842.13 | (230.16) | 94,611.97

The Balance Sheet and P&L keep their Notes column, which is what links a statement line to its note: (c) Deferred tax liabilities (net) | 21 | 215.24 | 1,198.28, Current tax | 5,606.07 | 5,848.54 (= Note 21's 5,701.41 − 95.34).

"Loaded" when the report is selected
  • Each statement's text is extracted once while indexing and cached inside the notes index (INDEX_VERSION 7). Every question reuses it without reading the PDF again. The first load of the sample report now takes about 12s (6s before); after that it is instant.
  • Step 1 of the UI shows a green box per section listing the loaded statements (✓ Consolidated Balance Sheet · PDF p.341). Each can be expanded to show the extracted text, and sideways statements carry a rotated tag.
  • Which statements go with a question: those of the selected notes' section (consolidated notes → consolidated statements, standalone → standalone, both → both). Manually entered pages use the consolidated set. Threads started before this feature get the statements added on their next follow-up.
  • The four consolidated statements add about 18,000 characters to a prompt, and the standalone four about 14,000. The MAX_CONTEXT_CHARS check now counts statements plus notes.

5. Stage 3: Choosing the Notes (note_selector.py)

Scope is decided by rules, not by the LLM. detect_scope() returns:

Question contains…Scope
nothing specialconsolidated (the default)
"standalone", "stand-alone", "parent company only", "not consolidated", "do not use consolidated"standalone
both "standalone" and "consolidated", or "standalone" with "both"both

Claude call #1 picks the notes. The prompt (prompts/selector_template.txt) lists only the notes in that scope, as IDs with titles and up to 8 sub-headings each. C means Consolidated and S means Standalone:

selector prompt (excerpt)
QUESTION: Analyze the company's Tax related liablities and comment on it.
Scope already decided: consolidated financial statements. Do not change it.
...
C20: PROVISIONS  [sub-headings: ...]
C21: INCOME AND DEFERRED TAXES  [sub-headings: Statement of profit and loss:; Profit or loss section; ...]
C22: TRADE PAYABLES  [sub-headings: ...]
...
Reply with ONLY this JSON (no markdown fences, no other text):
{"notes": ["C21"], "reason": "one or two sentences explaining the choice"}

The reply is parsed by finding the first {...} in it. Unknown IDs are dropped and at most 5 notes are kept. On the real run this call took 6 seconds and returned C21 (Income and deferred taxes), plus C41 (Contingent liabilities, where tax disputes sit), C23 and C19 as related notes.

  • Fallback: if the call fails or returns bad JSON, keyword_select() scores each note title against a synonym table (tax → "tax", debt → "borrowings", litigation → "contingent liabilities", …). The UI then says "Chosen by keyword match" instead of "Chosen by Claude".
  • Explicit references win: "…and also Note 41" always puts Note 41 first, whatever the selector says.
  • The result goes back to the browser, which always pauses on the confirmation card. Each note is a removable chip showing its PDF and printed pages. An "Add note" dropdown lists every note, and there is an option to type PDF pages instead.

6. Stage 4: Extracting the Note (extractor.py)

For each page of a note, extract_note() keeps only the text inside the note's exact extent:

  • First page: only text below the note's heading (start_y).
  • Last page: only text above the next note's heading (end_y).
  • Every page: nothing from the running header (report title, "Notes to…", "for the year ended…") or the footer (printed page number). These limits come from each page's top/bottom stored in the index.
  • (CONTD.) heading repeats are dropped. Ligatures such as ﬁ are normalized, and the report's Rupee font, which draws ₹ as a backtick `, is mapped back to ₹.
  • Each page is labelled, e.g. --- PDF page 405 (printed page 402) ---, so Claude can cite pages.
Dead end: PyMuPDF's table finder

The notes' tables have no ruling lines. page.find_tables(strategy="lines") returned one 3×2 "table" covering the whole page. strategy="text" cut words in half across columns (|Integrated Ann|ual Repor|t 2025-26|, |Partculars|). Plain get_text() wrote every number on its own line, which loses which column (FY26 or FY25) a number belongs to.

Fix: rebuild rows from text spans, and turn wide gaps into columns

_rows_to_text() groups spans whose vertical centres are within 3pt into one row and sorts each row left to right. Wherever the horizontal gap between two spans is more than COLUMN_GAP = 12pt, it inserts | . Ordinary prose has only 2–3pt between spans, so paragraphs stay intact. Two numbers next to each other are always split, however close they are (added for the equity statement; see Section 4). The real output for Note 21:

Rotated text (landscape pages) is collected separately and appended under [Rotated text on this page:], so it is never mixed into the horizontal rows. If the combined extract is over MAX_CONTEXT_CHARS (150,000), the analysis is refused with a message asking the user to remove a note.

7. Stage 5: Talking to Claude Code (claude_client.py)

Why basic-chatbot's exact invocation wasn't enough

basic-chatbot places the whole prompt inside a PowerShell -Command string. That works for chat, but a multi-note extract can be tens of thousands of characters, and Windows limits a command line to about 32K characters. It also needs quote escaping.

Fix: send the prompt on stdin, with every tool disabled
claude_client.py + config.py (excerpt)
CLAUDE_EXTRA_FLAGS = ["--tools", "", "--no-session-persistence"]

args = [config.CLAUDE_EXE, "-p", "--system-prompt", system_prompt] + config.CLAUDE_EXTRA_FLAGS
result = subprocess.run(args, input=prompt, capture_output=True, text=True,
                        encoding="utf-8", timeout=timeout, cwd=config.BASE_DIR)
  • --tools "" (checked against claude --help, v2.1.282) disables all built-in tools. Claude can therefore only analyze the text it is given; it cannot open files or run commands. A test call confirmed it: "I have no callable tools in this session."
  • --no-session-persistence: each call is stateless and isn't saved as a resumable session.
  • No --model flag, so the call uses whatever model Claude Code is set to. Set CLAUDE_MODEL to override it.
  • basic-chatbot's PowerShell route is still available with CLAUDE_VIA_POWERSHELL=1. PowerShell 5.1 drops empty-string arguments, so --tools "" can't pass through it. That route blocks tools by name with --disallowedTools instead, and refuses prompts over 25,000 characters.
The analysis prompt

prompts/analysis_system.txt makes Claude a senior financial analyst and forensic accountant. It is told it receives two kinds of material: the primary financial statements and the selected notes. Its rules: base every statement on that material; cite every figure as (Note 21, p.405) or (Balance Sheet, p.341); always connect the notes to the statements, i.e. find the lines each note supports (via the statements' Notes column), check that the figures agree, and explain the effect on each of the four statements; show calculations; flag inconsistencies, including note figures that don't match the statements; say so when information is missing; read | as a column separator; and treat the equity statement's jumbled multi-line column headings with care. prompts/analysis_template.txt fills in the report, scope, notes, question and extract, and asks for this structure:

Summary Key figures Detailed analysis Impact on the financial statements Red flags & areas for follow-up Sources

The Impact on the financial statements section has one sub-heading per statement (Profit and Loss, Balance Sheet, Cash Flow, Changes in Equity). For each one, Claude names the lines affected with their current- and prior-year figures, shows how the note reconciles to them, and explains the effect. The template places the statements block ({{STATEMENTS}}, listed in {{STATEMENTS_LIST}}) before the notes block ({{EXTRACT}}). The follow-up template carries both blocks too, and asks for a short impact section whenever figures are involved.

Templates use {{KEY}} placeholders, filled in one pass by fill_prompt(). Text inside the extract that happens to look like a placeholder is therefore never substituted a second time. All prompts live in prompts/ and can be edited without touching the code.

8. Background Jobs & Follow-up Threads

Jobs. An analysis takes 1–3 minutes, too long to leave a browser request waiting. /api/identify, /api/analyze and /api/followup each start a background thread and return a job_id straight away. The browser polls GET /api/jobs/<id> every 1.5s and shows a spinner with a running "Ns elapsed" counter. Jobs live in memory (JOBS dict), so the app runs with use_reloader=False to keep them alive. The polling requests are filtered out of logs/app.log.

Threads. Every analysis starts a thread saved as cache/threads/<id>.json. It holds the report, the notes, the extracted text and every turn. A follow-up is a new stateless claude -p call whose prompt (prompts/followup_template.txt) includes:

  1. the same extract,
  2. "Conversation so far" (the last 10 turns, as User asked / You answered, the same idea as basic-chatbot's session_context()),
  3. the new question.

If a follow-up mentions a note that isn't in the thread yet ("Also consider Note 41 tax disputes"), that note is extracted and added to the thread before the call.

UI issue: the follow-up spinner appeared at the top of the page

There was one shared progress element, placed below Step 3. When a follow-up was asked at the bottom of a long analysis, the "Asking Claude…" spinner showed up far off-screen at the top, so it looked as if nothing was happening.

Fix: the spinner moves to where the question was asked

runJob(url, body, label, anchor) moves the progress card and error box to just below anchor, which for follow-ups is the follow-up box, and scrolls to it. The question stays in the box as read-only until the answer arrives. A comment node marks the original position, so New analysis can put everything back.

9. Stage 6: Presenting & Saving the Analysis

In the app. render_markdown() first escapes < and &, so nothing in Claude's reply can inject HTML, then converts the Markdown (tables, fenced code and lists) to HTML. Each answer has Copy, .md, .html and Open saved report ↗ buttons. A collapsible Source sent to Claude (financial statements + notes) panel shows exactly what Claude saw, and the result header lists the statements used.

Every question and follow-up is saved in three places:

WhereWhat
claude-prompt-input.txt / Claude-prompt-output.txtThe last prompt sent and the last reply received (basic-chatbot pattern).
Prompt-History\Claude-code-prompt-N-*.txt-question.txt (a metadata header with time sent, kind, report, scope, notes, PDF pages, financial statements, thread and saved HTML, then the question), -answer.txt, and -prompt.txt (the full prompt including the extract, so any answer can be reproduced). The History sidebar reads these and can reopen a whole thread to continue it (see Section 10).
Analysis-history\<pdf name>-<n>-<YYYYMMDD-HHMMSS>.htmlA styled, standalone report. n is 1 for the first question, 2 for the first follow-up, and so on. The timestamp is when the prompt was sent. Example: Bharat-Forge-IR-2026-conv-single-page-1-20260924-173714.html.
The saved HTML report (report_html.py + templates/analysis_report.html)
  • A navy top bar with the RAG Champ logo on the left (the SVG is embedded, so the file works on its own anywhere) and ANNUAL REPORT ANALYZER on the right.
  • A light-blue box with the company name (Bharat Forge Limited), the annual report file, statements, notes, PDF pages analyzed, the financial statements referenced (e.g. Consolidated Statement of Changes in Equity (PDF p.344–345)), time sent and the question. Follow-ups also show the original question and a badge such as #2 · Follow-up question 1.
  • The analysis, with tables styled like the reference report (yellow header, alternating blue rows). Numeric cells such as (95.34), 34.66% and (2.60) pp are right-aligned.
Bug: lists merged into one run-on paragraph

Claude often writes a bold label with list items directly under it (**The P&L tax charge ties out:** then - FY26: …). Python-Markdown only starts a list after a blank line, so the page showed "ties out: - FY26: 5,701.41 … - FY25: …" as one paragraph, both in the app and in the saved report.

Fix: insert the missing blank line before rendering

_separate_lists() adds a blank line before any list item that directly follows a non-list line. It skips fenced code and table rows. A headless-Edge screenshot of the saved report confirmed that the calculation bullets now render as proper lists.

10. History Access (history.py + the History sidebar)

What the user sees

When the home page opens, the left sidebar lists past analyses, newest first. Each item shows the question (up to 140 characters, in two lines) and a grey line such as #9 · 2026-09-24 21:47:28 · Bharat-Forge-IR-2026-conv-single-page.pdf. Follow-up questions are marked ↳. The ☰ History button in the top bar shows or hides the sidebar, and ↻ reloads the list. Clicking an item shows that analysis in the main area. If its conversation is still on disk, the user can carry on asking follow-ups.

Where the information comes from

History has no database. It reads files that every analysis and follow-up already writes (Section 9):

SourceWhat History uses it for
Prompt-History\Claude-code-prompt-N-question.txtThe list and the header data. The file name gives the number N. A metadata block (one Key: value per line) is followed by a blank line and then the question.
Prompt-History\Claude-code-prompt-N-answer.txtClaude's reply (Markdown), shown when the item is opened.

A real question file (entry #9, a follow-up):

Prompt-History/Claude-code-prompt-9-question.txt (excerpt)

Get information related to this item as shown below and do additional analysis "Note 19: ...

history.read_entry(N) splits the file at the first blank line. Each header line matching ^([A-Za-z ]+): (.*)$ becomes a meta field (Asked at, Kind, Report, Scope, Notes, PDF pages, Financial statements, Thread, Saved HTML), and the rest is the question. It also reads the matching -answer.txt. The numbering and file layout are reused from basic-chatbot, which is why numbering carries on across restarts and days (next_sno() takes the highest number on disk plus 1).

The flow
history: list, then open

   app.js loadHistory() ──GET /api/history──► history.list_entries()

   ◄── JSON list ── draws one <li> per entry (↳ for follow-ups), click → openHistory(N)

click an item
   app.js openHistory(N) ──GET /api/history/N──► read_entry(N) + answer

STEP 1 — The sidebar list is built
WEB-APP/static/app.js→WEB-APP/app.py→WEB-APP/history.py

loadHistory() runs when the page loads, when ↻ is clicked, and after every finished analysis or follow-up (from startThread() and followup()), so a new answer appears at the top straight away. It calls GET /api/history, and history.list_entries() finds every Claude-code-prompt-*-question.txt. It sorts them by number, newest first, keeps the latest 100, and returns a short record for each. The browser builds each list item with textContent (never HTML), so a question can't inject markup into the page. If the call fails, the sidebar just stays as it was, since history is optional.

STEP 2 — The user clicks an item; the entry is fetched
WEB-APP/static/app.js→GET /api/history/<N>

openHistory(N) calls GET /api/history/N. The route reads the question and answer files, turns the answer into HTML with render_markdown() (which escapes HTML and fixes lists, as in Section 9), and sets thread_available to true only if the Thread: id is a valid 32-character hex id and cache/threads/<id>.json still exists. An unknown N returns 404, and the error box shows the message.

STEP 3a — Thread available: the whole conversation reopens
GET /api/threads/<id>→cache/threads/<id>.json

The browser then calls GET /api/threads/<id>. load_thread() reads the JSON, and every turn's answer is rendered with render_markdown() again. Because answers are rendered at display time, old answers benefit from later rendering fixes such as the list fix. In the main area:

  • If the thread belongs to another report, or no report is loaded yet, the report dropdown switches to it and selectReport() reloads its index and statements, so Step 1 matches the conversation.
  • The result card is cleared, and every turn of the thread is drawn with addTurn(): the question bubble, the rendered answer, Copy / .md / .html / Open saved report ↗, and the time and #N. Clicking any item of a thread (the first question or one of its follow-ups) opens the same full conversation.
  • The header line lists the report, notes and statements. Source sent to Claude (financial statements + notes) is filled from the thread's saved statements and extract.
  • state.threadId is set and the follow-up box is shown, so the next question continues this thread. It is sent with the same notes and statements and the conversation so far (Section 8), becomes the next prompt number, and is saved as the next …-<n>-<time>.html report.
STEP 3b — No thread file: a read-only view
WEB-APP/static/app.js

If the thread file is gone (e.g. cache\ was cleared) or the entry pre-dates threads, the page shows just that one question and answer. The time comes from Asked at, the report and notes from the metadata, and Open saved report ↗ from Saved HTML. The source panel and the follow-up box are hidden, because there is no saved extract to continue from.

STEP 4 — The page settles on the result
WEB-APP/static/app.js

The note-confirmation card (Step 3 of the main flow) is hidden, the result card is shown and scrolled into view, and the buttons are refreshed. From here the user can read, copy or download the answer, open its saved HTML report, ask a follow-up (3a only), or click New analysis to go back to asking a fresh question.

Design notes
  • Files, not a database. History survives restarts and can be browsed without the app. Any past answer can be reproduced from its -prompt.txt, which holds the exact prompt that was sent.
  • Two levels of storage. Prompt-History keeps each question and answer forever. cache\threads keeps what is needed to continue a conversation. Deleting cache\ removes the ability to continue, but never the history itself (Step 3b).
  • Safety. Thread ids are checked against [0-9a-f]{32} before any file is opened, list text is inserted as text, and answers go through the escaping render_markdown().
  • Covered by tests/test_app.py: after an analysis and a follow-up, /api/history returns both (follow-up first), the entry's PDF pages, Financial statements and Saved HTML metadata are correct, thread_available is true, and /api/threads/<id> returns both turns with their saved reports.

11. The "View the Financial Statements" Page (statements_view.py)

Below the two green "financial statements loaded" boxes in Step 1 there is a View the financial statements ↗ link. It points to GET /statements?report=<pdf> with target="_blank", so it opens in a new tab, and it only appears once statements have been loaded. The page is built entirely from the already-extracted statement text cached in the index; it does not read the PDF again. It uses the same design as the saved analysis reports:

  • The navy RAG Champ bar, and a light-blue box with the company name, the report file and a contents list with links to each statement (the equity statement marked rotated).
  • Consolidated Financial Statements first (P&L, Balance Sheet, Cash Flow, Changes in Equity), then Standalone Financial Statements.
  • Each statement page is captioned with its PDF and printed page, and rotated pages are tagged printed sideways; rotated 90° clockwise before extraction.
Turning a | b | c rows back into a table

statements_view._parse_page() lays each row out as label | Notes | value columns:

  • Trailing numeric cells are values, and they are right-aligned into the last columns, so current- and prior-year figures line up even when a row has no note number (Purchase of stock in trade | 788.71 | 2,318.22).
  • A small integer such as 24 or 19a before the values goes into the Notes column. A note-only row such as Income tax expense | 21 doesn't slide into a year column.
  • Rows made only of heading words (Notes | Year ended | Year ended, March 31, 2026 | March 31, 2025) become yellow header rows. Upper-case or lettered rows (INCOME, ASSETS, A. EQUITY SHARE CAPITAL:) become section rows. Total…, Profit for/before… and unlabelled subtotal rows are bold totals.
  • Wrapped labels are joined back onto their row (…stock in trade, dies + and scrap), and the signature block from "As per our report of even date" onwards is left out.
Bugs found by screenshotting the rendered page
  • Part A was squeezed. In the equity statement, part A (share capital, 3 value columns) and part B (other equity, 12 value columns) were one table, so part A's labels were crushed into a narrow column.
  • A heading was merged into a row of figures. A line starting with "(" was treated as a wrapped label, so (2) For the year ended March 31, 2025 was appended to the 956.27 | - | 956.27 row above it.
  • A regression from fixing that. After "(" lines stopped joining rows that have figures, (Loss), the wrapped end of - Other Comprehensive Income/, showed up as a row of its own.
Fixes
  • Each lettered part (A. …, B. …) starts its own table with its own column count: part A has 3 value columns, part B has 12.
  • A "(…)" line continues the row above only if that row has no figures yet (the EPS heading's (March 31, 2025: ₹2/-)) or the line contains no digits ((Loss)). (2) For the year ended … therefore stays a row of its own.
  • Verified by tests in tests/test_statements_view.py and by headless-Edge screenshots of the P&L, the Balance Sheet and the rotated equity statement.
Bug: the equity table was missing its column headings

The user's screenshot showed the Statement of Changes in Equity with no real headings. Its 12 columns are headed by stacked, wrapped words ("Securities / premium", "Retained / Earnings", "Foreign / currency / translation / reserve / (FCTR)"). The " | " text rows had lost which word sits over which column, so the headings came out as jumbled italic text ("Securities Capital Employee General Retained Foreign Equity Non- Cash flow…"). Some neighbouring heading words are also only 11pt apart ("Employee" / "General"), so the text flattener had merged them into one cell.

Fix: rebuild every statement table by position

When a report is loaded, extractor._rows_with_positions() now stores each statement row as separate spans with their x-positions (page["rows"] in the index, INDEX_VERSION 7). statements_view.parse_page() then uses the geometry:

  • Columns are clusters of the numbers' right edges, since figures are right-aligned. Each figure goes to the nearest column, so every statement's figures now sit in their true columns.
  • Heading words go to the column they sit over, and all heading rows between two rows of figures are merged per column, top to bottom. "Non-" + "controlling" joins as "Non-controlling". A heading that starts in the label area but is centred over a column ("Notes") or right-aligned to its edge ("Balance as on April 1, 2025") also belongs to that column.
  • Group headings that cover several columns are printed centred, so their span is widened symmetrically while it stays centred on the text. This gives Attributable to the owners of the parent over 9 columns, Reserves and Surplus (Refer note 16) over 5 and Items of OCI (Refer note 16) over 4.
  • Lettered parts must be all caps ("A. EQUITY SHARE CAPITAL:"), so the Balance Sheet's "I. Non-current assets" no longer splits its table. Wide tables use a compact style so all 12 columns fit.

Result for the consolidated equity statement: Securities premium · Capital reserves · Employee stock option outstanding · General reserve · Retained Earnings · Foreign currency translation reserve (FCTR) · Equity instruments through other comprehensive income · Non-controlling interest reserve · Cash flow hedge reserve · Total attributable to the owners of the Company · Non-controlling interests · Total. The standalone equity statement gets its 7 headings the same way.

Claude benefits too: for tables with 5 or more columns, the statement text sent to Claude now starts with the rebuilt headings, e.g. [Column headings, left to right: 1) Securities premium | 2) Capital reserves | … | 12) Total].

12. Old Annual Reports (Companies Act 1956)

Reports from before about 2011 (old Schedule VI) have no "Notes to … Financial Statements" running headers. The 1976-77 Reliance Textile Industries report, for example, has:

  • a Balance Sheet and a Profit and Loss Account; there is no Cash Flow Statement or Statement of Changes in Equity
  • Schedules 'A'–'N' "forming part of" them, cited in a Schedule column
  • Schedule 'O' with 34 numbered, mostly untitled notes
  • a Financial Summary, a Directors' Report and an Auditors' Report

report_format.py counts cheap text signals on every page, such as SCHEDULE headings and "forming part of the Balance Sheet". Modern reports win ties. If a report is legacy, legacy_index.py builds the index:

  1. Pages: pages printed sideways are turned first. The running header, including the repeated "SCHEDULE FORMING PART OF THE BALANCE SHEET" line, and the page number are cut off.
  2. Markers: statement titles, SCHEDULE headings, report-section titles, signature blocks ("As per our Report…") and divider pages. Each unit runs to the next marker, so schedules that share a page are split exactly.
  3. Units: they go into the section's notes list with ids SCH-E, N25, DIR/AUD/SUM. Numbered notes are the n. lines at the left margin of the notes schedule, in sequence. Untitled notes use their first words as the title.
  4. Text: quote marks around schedule letters (‘A’, `L', �C�) become 'A', and lost dashes become "–". Figures are never corrected.

The prompts get a REPORT PROFILE (format, year end, Rs. and lakhs, which statements exist and which don't), impact sections for the existing statements only, and prompts/analysis_system_legacy.txt. That file tells Claude to:

  • state amounts in Rs. lakhs/crores
  • flag figures that don't add up as possible transcription errors
  • annualise a prior period that isn't 12 months
  • derive a funds-flow when cash matters
  • use the law of the era

Modern-report prompts are unchanged, byte for byte. Design and decisions: INFO/ANALYZE-OLD-REPORTS-FUNC-PLAN.md.

13. Scanned Reports (OCR)

A PDF with text on fewer than 10% of its pages is a scanned report, e.g. BRK-1968.pdf: 39 microfilm images of Berkshire Hathaway's 1968 Form 10-K. It is transcribed once by ocr_transcribe.py:

  1. Page image: each page is rendered to a 150 dpi greyscale PNG in cache/<report>.ocr/.
  2. Claude call: claude -p --tools Read runs with that folder as its working folder and prompts/transcribe_page.txt. It returns a JSON page description (page type, company, statement title, schedule, headings, printed page) and the page as Markdown, with tables kept, figures copied exactly, and [?] for unreadable characters.
  3. Parallel and resumable: 4 pages at a time; pages already done are skipped. A page with 5 or more [?] is read again at 200 dpi.
  4. Checks (ocr_quality.py):
    • totals that equal the figures above them "tie" (sums, differences, subtotals in another column)
    • "Total" or unlabelled rows that don't tie are flagged
    • if Tesseract is installed, figures that neither it nor a tie confirms are flagged
    On BRK-1968: 137 totals tie and 1 doesn't. That one is p.23, where the scan's 405,5?1 was read as 405,531 but 405,581 makes the column add up.

transcribed_index.py then builds the index from the page descriptions:

  • One section per company: Berkshire Hathaway (consolidated), National Indemnity, National Fire & Marine.
  • Statements are grouped by title.
  • Notes are split at their ### (n) headings.
  • Schedules are grouped by label (I, III, V…).
  • Reports: each company's auditors' report and the filing text.
  • Ids carry a company code: BH-N5, NI-N6.
  • Extracts are line ranges of the cached Markdown.

Selection:

  • The scope is the company the question names; the default is the registrant, and "subsidiaries" means all the others.
  • The prompt adds a REPORT PROFILE, the TRANSCRIPTION CHECKS for the pages used, and analysis_system_transcribed.txt: treat [?] as unknown, verify figures against totals, and cite pages.

The Review transcription page (/ocr-review) shows each page image next to its transcription and flags, with a Re-transcribe this page button. Design and decisions: INFO/OCR-CAPABILITY-PLAN.md.

16. Known Limitations

  • Old reports (§12) have been verified on one sample only, the re-typeset Reliance 1976-77 report. Other old layouts, such as numbered schedules or a separate "Notes on Accounts" section, are handled by the same patterns but not yet tested.
  • Scanned PDFs (§13) need a one-time transcription: about $0.14 and 9 s per page, with 4 pages in parallel. Figures can be misread, so check the flagged ones on the Review page.
  • Other companies' layouts: heading detection is font-based and generic, but it has only been verified on the Bharat Forge report. Other running-header wordings can be added to NOTES_HEADERS in config.py. If no notes are found, the user can still type PDF pages manually.
  • Finding the statements: they are expected within the 15 pages before each notes section, with a large title (14pt or more) naming the statement. Verified only on the Bharat Forge report.
  • Longer analyses: sending the statements adds about 18,000 characters to every prompt. The sample tax analysis went from 79s to 127s.
  • Jobs are in memory: restarting the server during an analysis loses that job. Threads, history and saved reports are on disk and survive a restart.
  • Local tool: it binds to 127.0.0.1 only, the same as basic-chatbot. There is no authentication.

17. Glossary

TermMeaning
Notes to financial statementsThe numbered footnotes after the primary statements that break down each line item (e.g. Note 21, Income and deferred taxes).
Consolidated vs. standaloneConsolidated covers the whole group (parent plus subsidiaries). Standalone covers only the parent company. Each has its own set of notes.
PDF page vs. printed pageThe page's position in the PDF file (used by the app) vs. the number printed on the page. In the sample report, printed = PDF − 3.
Primary financial statementsThe Statement of Profit and Loss (income statement), Balance Sheet, Cash Flow Statement and Statement of Changes in Equity (stockholders' equity). The app loads them for both sections and sends the relevant set with every question.
Sideways (rotated) pageA page whose content is printed turned 90° (text direction (0, -1)), like the consolidated Statement of Changes in Equity. It is redrawn turned clockwise before extraction.
Impact on the financial statementsThe answer section that ties the note to statement line items and explains its effect on the P&L, Balance Sheet, Cash Flow and Changes in Equity.
Running headerThe repeated heading at the top of every notes page ("Notes to Consolidated Financial Statements / for the year ended …").
Notes IndexThe cached JSON map of every note: number, title, start and end page, y-positions, printed pages and sub-headings.
Span / rowA span is a run of text in one font from PyMuPDF. A row is the spans sharing one baseline, merged by page_rows().
ScopeWhich set of notes a question uses: consolidated (default), standalone or both.
Selector callClaude call #1, which picks note IDs from titles only.
ExtractThe clipped, cleaned text of the selected notes that is sent to Claude.
JobA background thread running identify, analyze or follow-up, which the browser polls by ID.
ThreadOne analysis and its follow-ups, sharing the same extract (cache/threads/<id>.json).
History entryOne numbered question and answer in Prompt-History\ (Claude-code-prompt-N-*.txt). The sidebar lists them. Opening one reopens its whole thread when cache\threads\<id>.json still exists (Section 10).
Prompt numberThe position within a thread: 1 is the initial question, 2 the first follow-up, and so on. It is used in the saved report's file name.
claude -pClaude Code's print mode: one non-interactive request and response, then exit.
