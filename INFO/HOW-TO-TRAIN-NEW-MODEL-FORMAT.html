How to Train a New Model Format

The analyzer only reads report formats it has extraction rules for. Each format is represented by one model document in MODEL-DOCS\, and a report that matches none of them is refused as a new model document. This guide shows how to add a new format: where to put the PDF and how to name it, the exact prompt to give Claude Code, how to check what it did, and a worked example of how the rules for three real formats (Magna's 40-F, Infosys's and BHP's 20-F) were written, with the critical decisions taken along the way.

1. The Big Picture

Every report the user selects is first matched to a model document. A match means the report is read with that model's extraction rules (its profile). No match means it is blocked, and the app writes a gap report saying what differs. Training a new format means giving the app a new model document and the rules to read it:

You                                   Claude Code (in this project)                 You
─────────────────────────────         ─────────────────────────────────────────     ─────────────────────────
1. copy the PDF into MODEL-DOCS\  ─►  3. study the layout, write the rules          5. test pages on the
   with the TYPE-n-… name              (a profile + switches), register the           Model testing screen,
2. (optional) look at the gap          model, check the extraction against the        ask a question,
   report on the Ingest screen         PDF, add a test, run verify + all tests  ─►    rebuild the exe
                                   4. report back what it did and found

The work in step 3 is deliberately done in a Claude Code session you can watch, not by a button in the app. Writing rules takes judgment (Section 10), and every change is checked against all the other formats before it is kept.

Words used in this guide
TermMeaning
Model documentOne PDF in MODEL-DOCS\ that stands for one report format. Each document is its own model; its id is its file name.
ProfileThe extraction rules for a format, in WEB-APP\ingest\profiles\__init__.py: which indexer reads it, which optional rules are switched on, and what a correct extraction must contain (acceptance checks).
SwitchAn optional rule that only the profiles that need it turn on, e.g. decimal_notes for notes numbered 2.1, 2.2. A new format never changes another format's code path.
RegistryWEB-APP\ingest\models\registry.json: each model's checksum, profile, description and fingerprint. Changed only with python -m ingest.models.
PendingA model registered without rules yet. Its reports are refused, but its pages can already be viewed on the Model testing screen.
Prompt baselineFrozen copies of every prompt the five sample reports produce (tests\fixtures\baseline\). If a change alters any of them, the tests fail. This is how "no other format changed" is proved.

2. Before You Start

  • Claude Code is installed and logged in, and you can open it in C:\Daya\RAGchamp\ANN-RPT-ANALYZER (the folder that holds .claude\CLAUDE.md, so Claude Code reads the project guide).
  • The app's tests pass before you start: in WEB-APP, python -m pytest -q (about 5 minutes, no Claude usage). Then any failure afterwards is caused by the new rules.
  • Time and usage: a new format takes Claude Code roughly 20–60 minutes and a fair amount of Claude usage, more if the layout is unusual. Stay with the session: it may ask you a question.
  • One format at a time. Train, test and rebuild before starting the next one.
Make sure the PDF is the right document

The PDF must contain the primary financial statements and their notes. The first Magna PDF was its Annual Information Form: 132 pages with no statements and no notes at all, so no rules could ever make it analyzable. A Form 40-F files the statements as a separate exhibit (Exhibit 99.3), and that exhibit was the right model document. If you are unsure, open the PDF and look for "Consolidated Balance Sheet" and "Notes to … Financial Statements".

C:\Daya\RAGchamp\ANN-RPT-ANALYZER\MODEL-DOCS\

Put the PDF directly in this folder, not in a sub-folder (_candidates\ is for reports the app proposed). The folder is not in git and is not shipped in the exe; the registry keeps each PDF's checksum instead.

STEP 1b — Name it with the convention

TYPE-9-CANADA-40-F-2025-Company.pdf

PartRuleExamples
TYPE-nThe next free number. Today TYPE-1 … TYPE-8 are taken, so the next one is TYPE-9.TYPE-9, TYPE-10
COUNTRYThe company's country, in capital letters, one word.INDIA, USA, CANADA, AUSTRALIA, UK

5. Step 3: The Prompt to Give Claude Code

Open Claude Code in C:\Daya\RAGchamp\ANN-RPT-ANALYZER, then paste this prompt. Change only the file name on the second line.

Prompt for Claude Code — train a new model format
Train a new model format for the Annual Report Analyzer.
The new model document is MODEL-DOCS\TYPE-9-CANADA-40-F-2025-Company.pdf

1. Read .claude\CLAUDE.md (sections 7 and 9) and MODEL-DOCS\README.md. Run
   python -m ingest.models match on the new PDF, and trial every existing profile on it,
   to see what the current rules already find.
2. Study the PDF's layout: where the four primary statements are and how they are titled,
   how the notes are headed and numbered, where the notes end, and how the statements
   cite the notes.
3. Write its extraction rules as a new profile in WEB-APP\ingest\profiles\__init__.py.
   Reuse an existing profile with derive() where its rules already work. Put every new rule
   behind a new profile switch so that no other format changes. Choose wording checks that
   no other model document contains.
4. Register it: python -m ingest.models register "..\MODEL-DOCS\<file>.pdf"
   --profile <id> --description "..."
5. Check the extraction against the PDF itself: every note's number, title and pages; the
   four statements and their pages; a few figures with their periods and units; and one
   statement line's link to its note.
6. Add a golden test like WEB-APP\tests\test_20f.py. Run python -m ingest.models verify
   and python -m pytest -q. The other reports' prompt baseline must stay byte-identical;
   don't re-freeze it.
7. Update WEB-APP\README.md, INFO\HOW-ANN-RPT-FOOT-NOTE-ANALYZER-WORKS.html,
   MODEL-DOCS\README.md and .claude\CLAUDE.md. Don't commit.
8. Report back: the rules you wrote and why, what the extraction found, the test and
   verify results, and anything it still gets wrong.

Claude Code asks for permission before running commands or editing files, unless you have allowed them. Say yes to the steps above; say no to anything that would commit, delete a model document or re-freeze the prompt baseline.

Why each line of the prompt is there
Prompt stepWhat it prevents
1 · Match and trial every profile firstWriting new rules for a format an existing profile nearly reads already. Magna needed only new wording checks.
3 · New rules behind a switchA fix for the new format changing how Bharat Forge, Chubb or Berkshire are read.
3 · Wording no other model hasTwo formats both accepting the same report. The matcher then can't decide, and the report is refused as a new model.
5 · Check against the PDF itself"Checks passed" on a wrong result. The acceptance checks only count notes and statements; they don't read titles.
6 · Baseline must stay identicalA shared-code change quietly altering another report's prompts. This happened once and was caught (Section 8, step 6).
7 · Don't commitChanges you haven't reviewed and tested going into git.

To see the code changes, run git diff (or git status) in the project folder. They should be limited to the new profile and switches, the registry, a new test file, and the docs. Any change to shared code (such as figures.py) should come with an explanation of why the other reports stay the same.

Push back if you see…
  • A re-frozen prompt baseline (tests\fixtures\baseline\ changed): unless the change was meant to alter the other reports' prompts, a rule has leaked into another format.
  • An if for the new format in shared code instead of a profile switch.
  • "Checks passed" with no note list: ask Claude Code to list every note number, title and page range next to the headings in the PDF.
  • A changed or deleted existing model document or test, other than tests that assumed the old list of formats.

7. Step 5: Test It in the App, then Rebuild

STEP 5a — Restart the app

Python changes need a restart. Stop the server and run python app.py in WEB-APP. If port 5000 is still taken, see Stale servers in .claude\CLAUDE.md §9. The first report opened after the change is re-ingested once, because packages rebuild when the rules change.

STEP 5b — Test pages on the Model testing screen
http://127.0.0.1:5000/model-testing

Choose the new model document, then test a statement page, the first notes page, a note that spans several pages, and the last notes page. Each result shows the page image beside the notes and statements found on it, the page text and the statement lines. If something is wrong, tick Need correction, describe it and submit. The fix follows the feedback routine (.claude\CLAUDE.md §7a).

STEP 5c — Ask a real question

Copy the model PDF into Annual-reports\, select it on the Analyze screen and ask, for example, "Analyze the company's tax related liabilities and comment on it." Check that the suggested notes are right and that the answer's Impact on the financial statements quotes figures from the statements.

STEP 5d — Commit and rebuild the exe
C:\Daya\RAGchamp\PYTHON-EXEC-BUILDER\INPUT\PROJ-2\ANN-RPT-ANALYZER\WEB-APP

When you are happy, ask Claude Code to commit, or commit yourself. Then refresh the builder's copy of WEB-APP and rebuild the exe as described in .claude\CLAUDE.md §3. The registry and rules ship in the exe; the model PDFs don't.

8. Worked Example: BHP's Form 20-F

TYPE-8-AUSTRALIA-20-F-2025-BHP.pdf is a 363-page 20-F printed from the SEC website in a browser: the financial statements start at PDF page 279, and the notes run from 288 to 358. This is how its rules were written on 2026-09-28, step by step.

STEP 1 — What the existing rules find: nothing
match.trial(pdf, profile)→every existing profile

All three candidate profiles (in-indas-2020s, us-10k-edgar, ca-40f-usgaap) found 0 notes and 0 of 4 statements. Unlike Magna, BHP needed new rules, not just new wording.

STEP 2 — Study the layout: fonts, positions, headings
PyMuPDF page.get_text("dict")→ingest.pdf_utils.page_rows

Printing each line's position, size and font on the statement and notes pages showed four things:

  • Statement titles are numbered: 1.1 Consolidated Income Statement for the year ended 30 June 2026. The title test wants the text to start with a statement name.
  • The notes heading, 1.6 Notes to the Financial Statements, is printed once (p.288), not at the top of every page. The app only knew the wordings "Notes to (the) Consolidated / Standalone Financial Statements".
  • Note headings (1. Segment reporting, 24.3 Financial assets and liabilities) are ordinary bold numbered rows, which the existing heading logic already reads.
  • Each page carries the browser's print chrome: a date line (9/27/26, 1:05 PM 20-F), a "Table of Contents" link, and the page's URL at the bottom.
STEP 3 — Write the rules as switches
ingest/profiles/__init__.py→ingest/notes_index.py→ingest/statements.py
WEB-APP/ingest/profiles/__init__.py
AU_20F = derive(
    IN_INDAS, id="au-20f-ifrs", version=1,
    switches=Switches(notes_run_on=True, numbered_statement_titles=True,
                      extra_notes_headers=(("consolidated", "Notes to the Financial Statements"),)),
    acceptance=Acceptance(must_contain=(
        ("Form 20-F", r"\bForm\s+20-F\b"),
        ("an Australian company (Corporations Act 2001)", r"Corporations Act 2001"),
    )),
)

numbered_statement_titles ignores a leading "1.1" when testing a title. extra_notes_headers adds the wording for this profile only. notes_run_on keeps the pages after the heading in the notes until a page that starts the next part ("Item 19.", "SIGNATURES", the auditor's report). All three are off for every other profile.

STEP 4 — First trial: statements found, still 0 notes (a bug)

The statements were now found, but the notes section stopped at p.294 with no notes in it. Two causes:

  • The URL footer (https://www.sec.gov/…, at x=24) counted as body text, so the page's left margin became 24pt. A heading must start within 25pt of that margin, so every heading at x=130 was rejected. Fix: the print chrome, including the URL footer, is cut from the page layout on these pages.
  • p.295, inside note 4 (Samarco), holds a small table titled "Cash flow statement". It was detected as a statement page, which ended the notes. Fix: statements come before the notes, so a statement-like page after the notes start no longer ends them.

Second trial: 37 notes, PDF 288–358, all four statements, checks passed.

STEP 5 — Check against the PDF, not just the checks

Every note number, title and page range was listed and compared with the headings in the PDF (1 Segment reporting … 37 New and amended accounting standards). Then a figure: Total taxation expense had the right values and was linked to Note 6, but its period was missing. The column headings were US$M instead of 2026 / 2025 / 2024.

The cause: the unit row (Notes | US$M | US$M | US$M) sits under the years and replaced them. Fix, in shared code: a heading row that only names a unit keeps the years above it; US$M was added as a unit. Result: (9,388) FY2026, (7,210) FY2025, (6,447) FY2024, units US$M.

STEP 6 — Prove nothing else changed
python -m ingest.models verify→python -m pytest -q

verify checks that each of the eight models matches itself and that no other format's rules accept it. The test suite re-ingests the five sample reports and compares every prompt with the frozen baseline. Both passed: verify: OK, 312 passed.

This check has earned its place. While writing Magna's rules, a first version of a units fix also gave the 1994 Berkshire report a new "units" line, which changed its prompts. The baseline test failed, and the fix was narrowed to "U.S. or Canadian dollars in millions".

STEP 7 — Register, test, document
python -m ingest.models register→tests/test_20f.py→README, HOW doc, CLAUDE.md

The model was registered with its profile (the registry version went up, so existing packages are re-matched automatically). A golden test now pins down the facts: 37 notes; Note 6 on PDF 303–305; the notes ending at 358 and not at the "Cash flow statement" table; the statement pages; the tax line's figures and link. Last, the docs were updated.

9. Two More Examples: Magna and Infosys

TYPE-6 Magna (40-F exhibit): new wording only
  • Found: the Indian (Bharat Forge) rules already read all 26 notes, 4 statements and 264 figures. Only the Ind AS / ₹ wording check failed.
  • Rules: ca-40f-usgaap = the Ind AS profile with two new wording checks. The auditor signs as "Chartered Professional Accountants", the Canadian designation, which no other model contains; amounts are in U.S. or Canadian dollars.
  • Bug found: units read as "rs in millions". The rupee pattern matched the "rs" at the end of "dollars". It now needs a word boundary.
  • Accepted limit: the balance-sheet totals are unlabelled rows, so no balance check runs yet.
TYPE-7 Infosys (20-F): notes numbered 2.1, 2.2 …
  • Found: the statements were read, but only 1 note. The heading "Overview and Notes to the Consolidated Financial Statements" is printed once, and the notes are 1.1 … 1.6, then 2.1 … 2.21. The statements cite them as 2.1, 2.18.
  • Rules: in-20f-ifrs with notes_run_on, decimal_notes (the N.M headings are the notes, id C2.18) and untitled_statement_pages (p.172 continues the Changes in Equity with no title).
  • Bugs found: the Note column wasn't recognised. Its "Note" heading shares a row with the years, and "2.18" looks like a figure. The note-text header also crashed on a note numbered "2.1".
  • Accepted limits: no units line ("Dollars in millions" without "U.S."); 15 of 919 figures are multi-line equity column headings.

10. The Critical Decisions

These are the judgment calls that made the three formats work. A new format will usually meet some of them. They are also the reason training happens in a Claude Code session you watch, rather than from a button in the app.

DecisionOptionsChosenWhy
New rules or reuse?Write a new indexer · extend an existing profile with derive()Extend (all three derive from the Ind AS profile)The trial runs showed the layout logic already worked (Magna) or nearly worked (the 20-Fs). Less new code means less risk.
Where a new rule goesAn if in shared code · a profile switchA switch, off for everyone elseOther formats cannot change, and the switch names what the format needs (decimal_notes, notes_run_on).
When shared code must changeHide every fix behind a switch · fix a genuine bug for allFix for all, and prove it with the baseline"Rs" matching inside "dollars", and a unit row hiding the years, are bugs for any report. The prompt baseline showed no other report changed, after one narrowing.
Wording checksGeneric (IFRS, US GAAP) · distinctive phrasesPhrases no other model hasEvery document was searched: "Chartered Professional Accountants" (Magna only), "Form 20-F" + Ind AS (Infosys), "Form 20-F" + "Corporations Act 2001" (BHP). Generic words would let two formats accept the same report.
What counts as a note (Infosys)Notes 1 and 2 (one 80-page note) · the 2.1 sub-notesThe N.M headingsThe statements cite 2.1, 2.18, and a question about taxes should get the 7-page Income taxes note, not all 80 pages.
Where the notes endA fixed page count · stop phrases · next statement pageStop phrases ("Item 19.", "SIGNATURES", auditor's report)A statement-like table inside a note (BHP p.295) must not end the notes; the next part of the filing must.
Browser print chromeIgnore it · cut it from the layoutCut the date line, "Table of Contents" and URL footerLeft as body text, the URL footer moved the page margin, and every note heading was rejected.
Report format labelA new analyzer format (US GAAP statement names) · the generic "modern" format"modern"No analyzer or prompt changes were needed. Statement names in prompts stay generic; a new format would be a separate decision.
Which version to bumpThe profile's version · INDEX_VERSIONINDEX_VERSION for shared code (now 28), the profile version for rule changesPackages rebuild only when needed. Otherwise the tests and the app silently use old packages.
What to accept as a limitFix everything · document small gapsDocument themInfosys's missing units line and 15 heading cells don't affect answers (the statement text still says "Dollars in millions"); chasing them would add risky rules.

11. Troubleshooting

You seeWhat it means / what to do
match says it already matches a modelThe format is covered. No training is needed; test a few pages on the Model testing screen.
"This report is scanned"No text layer. Scanned reports use the scanned-ocr profile and must be transcribed on the Ingest screen first (this costs Claude usage).
You replaced a model PDF with another versionThe registry still has the old checksum. Ask Claude Code to re-register it and check its rules again, as was done when Magna's Annual Information Form was replaced by its financial statements exhibit.
Two models "equally close" → new model documentTwo profiles accept the report. Their wording checks are not distinctive enough; ask Claude Code to tighten them and run verify.
The tests fail in test_prompt_identity.pyA change altered another report's prompts. Don't re-freeze the baseline: ask Claude Code to move the change behind a switch or narrow it.
A page is extracted wrongly after trainingReport it on the Model testing screen (Need correction). Then give Claude Code the feedback file name; the fix routine is in .claude\CLAUDE.md §7a.
The Analyze screen still refuses the reportRestart the app (Python changes need a restart). Make sure the report in Annual-reports\ is the same file as the model document, or one with the same layout.
